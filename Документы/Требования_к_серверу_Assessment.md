# Требования к серверу и инфраструктуре
## Модуль Assessment (`test.zakupki.tatar`)

**Заказчик:** АО «Центр развития закупок Республики Татарстан»  
**Система:** изолированный модуль профессионального тестирования  
**Документ для:** передачи Заказчику (выделение / закупка / настройка оборудования)  
**Дата:** 07.08.2026  
**Версия:** 1.0  

---

## 1. Назначение сервера

Выделяется **отдельный** сервер (физический или виртуальный) под модуль Assessment.

| Требование | Значение |
|------------|----------|
| Публичное имя | `test.zakupki.tatar` |
| Изоляция | **Не** размещать на том же хосте / той же БД, что основной портал `zakupki.tatar` |
| СУБД модуля | **PostgreSQL** (отдельный инстанс/БД `asmt`) |
| СУБД портала | MySQL/MariaDB — **без изменений**, контуры не смешиваются |

> Модуль хранит персональные данные участников и результаты тестирования. Сервер должен соответствовать политике Заказчика по 152-ФЗ (размещение, доступ, бэкапы).

## 2. Два профиля мощности

В ТЗ заложена пиковая нагрузка **до 5000 одновременных активных сессий**. Ниже — два практических профиля.

### 2.1. Профиль «Старт / приёмка» (рекомендуется на выкат)

Достаточно для развёртывания, функциональных испытаний, пилотных кампаний, модерации и выгрузок.

| Ресурс | Минимум | Рекомендуется |
|--------|---------|---------------|
| vCPU | 4 | 8 |
| RAM | 8 ГБ | 16 ГБ |
| Диск | **40 ГБ SSD** | **60–80 ГБ SSD** (NVMe предпочтительно) |
| Сеть | 100 Мбит/с | 1 Гбит/с |
| ОС | Ubuntu 22.04 LTS / Debian 12 / аналог RHEL 8+ | то же |

> **Про объём диска:** модуль хранит в основном текст (пользователи, попытки, ответы, справочник). Сама БД на старте и при десятках тысяч попыток занимает **единицы гигабайт**, не сотни.  
> **20 ГБ** теоретически хватит *только* если: тонкая ОС, бэкапы **не** на этом диске, жёсткая ротация логов. На практике на одном томе живут ОС (~6–10 ГБ) + пакеты + PostgreSQL/WAL + логи + запас под рост → безопасный старт **от 40 ГБ**.  
> Ранее указанные 160 ГБ — завышенный запас «на бэкапы и рост»; для текстового контура не обязательны.

### 2.2. Профиль «Пик 5000 сессий» (high load)

Нужен для ПСИ по §5.1.3 ТЗ и массовых аттестационных кампаний.

| Ресурс | Минимум под пик | Рекомендуется |
|--------|-----------------|---------------|
| vCPU | 16 | 24–32 |
| RAM | 32 ГБ | 64 ГБ |
| Диск | 100 ГБ NVMe SSD | 150–200 ГБ NVMe; **бэкапы лучше на отдельный том / объектное хранилище** |
| Сеть | 1 Гбит/с | 1–10 Гбит/с |
| Дополнительно | PgBouncer; при необходимости 2-й узел (app / DB) | Redis для PHP-сессий (опционально) |

**Важно:** достижение ровно 5000 одновременных сессий зависит от выделенного железа. Исполнитель оптимизирует код и схему; Заказчик обеспечивает мощность. Фактический результат фиксируется в протоколе ПСИ.

Допустима схема: сначала выдать профиль «Старт», к массовой кампании — апгрейд или отдельный боевой контур.

## 3. Программный стек (обязательно)

| Компонент | Версия / требование |
|-----------|---------------------|
| ОС | Linux x86_64 (Ubuntu 22.04 LTS / Debian 12 / аналог) |
| Веб-сервер | **Nginx** + **PHP-FPM** (предпочтительно) или Apache + PHP-FPM |
| PHP | **8.1+** (рекомендуется **8.2/8.3**) |
| Расширения PHP | `pdo_pgsql`, `pgsql`, `mbstring`, `json`, `openssl`, `session`; желательно `opcache` |
| СУБД | **PostgreSQL 14+** (рекомендуется **15/16**) |
| Кодировка БД | `UTF8`, locale `ru_RU.UTF-8` или `C.UTF-8` |
| Пул соединений (для пика) | **PgBouncer**, режим `transaction` |
| SSL/TLS | сертификат на `test.zakupki.tatar` (Let’s Encrypt или корпоративный УЦ) |
| Почта | SMTP исходящий (см. §5) |

### 3.1. Что не требуется на сервере Assessment

- MySQL/MariaDB для модуля (только PostgreSQL);
- Docker (по желанию Заказчика; код разворачивается и без него);
- отдельный Node.js / Java runtime.

## 4. Сеть, DNS, доступы

| # | Требование | Ответственный |
|---|------------|---------------|
| 4.1 | A-запись `test.zakupki.tatar` → публичный IP сервера | Заказчик (DNS) |
| 4.2 | Открыты порты **80** и **443** с Интернета | Заказчик / сетевики |
| 4.3 | Порт **5432** PostgreSQL **не** публиковать в Интернет (только localhost / внутренняя сеть app→db) | Заказчик |
| 4.4 | SSH-доступ Исполнителю (ключ, sudo по согласованию) для выката и настройки | Заказчик |
| 4.5 | HTTPS обязателен до приёмки (обмен ПДн) | Заказчик + Исполнитель |
| 4.6 | Firewall: разрешить исходящий SMTP (25/465/587 — по политике) | Заказчик |

### 4.1. Связь с основным порталом

На `zakupki.tatar` уже подготовлена двухблочная модалка входа (кнопки ведут на Assessment).  
После появления DNS достаточно, чтобы ссылки указывали на `https://test.zakupki.tatar/...`.  
Сессии CMS и Assessment **изолированы** (разные cookie / `ASMTSESSID`).

## 5. Почта (SMTP)

Модуль отправляет:

- пароль при регистрации;
- ссылку восстановления доступа (Magic Link, 24 ч).

| Параметр | Нужно от Заказчика |
|----------|-------------------|
| SMTP host | например `smtp.….tatar` / корпоративный релей |
| Порт | 465/587 (TLS) |
| Учётная запись | логин / пароль или IP-разрешение |
| From | например `noreply@zakupki.tatar` или `noreply@test.zakupki.tatar` |
| SPF/DKIM | желательно для доставляемости |

До выдачи SMTP возможен временный режим логирования писем на сервере (`mail.log`) — **только для отладки**, не для приёмки боевого контура.

## 6. Рекомендуемые параметры PostgreSQL (ориентир)

Настраивает Исполнитель/админ при выкате; значения зависят от RAM.

### Профиль «Старт» (~16 ГБ RAM)

| Параметр | Ориентир |
|----------|----------|
| `shared_buffers` | 4 ГБ |
| `effective_cache_size` | 12 ГБ |
| `work_mem` | 16–32 МБ |
| `maintenance_work_mem` | 512 МБ |
| `max_connections` | 100–150 (за PgBouncer — меньше на стороне PG) |
| `wal_level` | `replica` (если понадобится реплика) |

### Профиль «Пик» (~64 ГБ RAM)

| Параметр | Ориентир |
|----------|----------|
| `shared_buffers` | 16 ГБ |
| `effective_cache_size` | 48 ГБ |
| `work_mem` | 32–64 МБ |
| `max_connections` | 200–300 **через PgBouncer** (к PG — десятки) |
| `checkpoint_completion_target` | 0.9 |

PHP-FPM (пик): пул `ondemand`/`dynamic`, ориентир `pm.max_children` исходя из RAM (не исчерпывать память).

## 7. Диски, бэкапы, мониторинг

| # | Требование |
|---|------------|
| 7.1 | Ежедневный бэкап БД: `pg_dump -Fc` (или непрерывный WAL-архив) |
| 7.2 | Хранение бэкапов **отдельно** от бэкапов MySQL портала, срок — по политике Заказчика (рекомендуется ≥ 14–30 суток) |
| 7.3 | Место под логи Nginx/PHP и ротация (`logrotate`) |
| 7.4 | NTP / синхронизация времени (важно для таймера теста 90 мин и Magic Link) |
| 7.5 | Мониторинг: CPU, RAM, диск, availability HTTPS, число соединений PG (Zabbix/Prometheus/иное — по стандарту Заказчика) |

## 8. Безопасность (минимум на стороне инфраструктуры)

| # | Требование |
|---|------------|
| 8.1 | Доступ к ОС только по SSH-ключам; парольный root снаружи — запретить |
| 8.2 | Автообновления безопасности ОС или регламент патчинга |
| 8.3 | Каталог кода и `.env` — права только на служебную УЗ (секреты не в git) |
| 8.4 | Резервное копирование `.env` / сертификатов — по процедуре ИБ Заказчика |
| 8.5 | Разграничение ролей: кто администрирует ОС / кто БД / кто приложение |

Прикладная безопасность (bcrypt, rate limit, валидация, аудит админов) реализована в коде модуля.

## 9. Что Заказчик передаёт Исполнителю при выдаче сервера

Чек-лист готовности инфраструктуры:

- [ ] IP / hostname, ОС установлена  
- [ ] DNS `test.zakupki.tatar` указывает на сервер  
- [ ] SSH-доступ Исполнителю  
- [ ] sudo / возможность установить Nginx, PHP-FPM, PostgreSQL (или уже установлены)  
- [ ] SSL-сертификат выпущен **или** доступ для Let’s Encrypt  
- [ ] Реквизиты SMTP  
- [ ] Подтверждение: PostgreSQL выделен под Assessment (не общая БД портала)  
- [ ] (Опционально) доступ в панель мониторинга  
- [ ] Реестр организаций (CSV/XLSX) для импорта справочника ИНН  
- [ ] Контакты админа ОС и ИБ на период выката  

После этого Исполнитель: выкат кода, миграции, seed вопросов, smoke-проверка по чеклисту, передача учёток суперадмина.

## 11. Краткая спецификация «одной строкой» для закупки VM

> Linux VM, 8 vCPU / 16 GB RAM / **60 GB SSD** (минимум **40 GB**), Ubuntu 22.04, публичный IP, DNS `test.zakupki.tatar`, HTTPS, исходящий SMTP; на ВМ: Nginx + PHP 8.2-FPM + PostgreSQL 16. Бэкапы — на отдельное хранилище.  
> Для кампаний с пиком ~5000 сессий: апгрейд до 16–32 vCPU / 32–64 GB RAM + PgBouncer (или отдельный DB-узел); диск при необходимости 100+ GB.
