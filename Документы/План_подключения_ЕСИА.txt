# План подключения модуля Assessment к ЕСИА (Госуслуги)

**Проект:** автоматизированный модуль профессионального тестирования (Assessment)  
**Система:** `https://test.zakupki.tatar`  
**Заказчик / оператор ИС:** АО «Центр развития закупок Республики Татарстан»  
**Учредитель:** Республика Татарстан  
**Документ для:** передачи Заказчику (организационно-правовой контур)  
**Дата:** 06.08.2026  
**Основание процедуры:** Регламент информационного взаимодействия с Оператором ЕСИА (актуальная редакция на портале ЕСКС / Минцифры России); инструкция «Как подключиться к ЕСИА» (актуализация 26.01.2026)

---

## 1. Краткий вывод

Подключение **входа через Госуслуги (ЕСИА)** для модуля Assessment — это **организационная процедура Заказчика** + последующая техническая настройка Исполнителем.

Для АО с учредителем в лице Республики Татарстан правовые предпосылки, как правило, **благоприятные**: организация относится к контуру региональной инфраструктуры закупок / квалификационной оценки специалистов и может обосновать подключение нормативными актами РТ и целями оказания госуслуг / функций в сфере закупок.  
Окончательное решение о подключении ИС принимает **федеральный операторский контур ЕСИА** (заявки — в ситуационный центр электронного правительства).

**Главный официальный адрес подачи заявок на подключение ИС к ЕСИА:**  
**sd@sc.digital.gov.ru**

Официальная памятка: [Как подключиться к ЕСИА (ЕСКС)](https://info.gosuslugi.ru/articles/%D0%9A%D0%B0%D0%BA_%D0%BF%D0%BE%D0%B4%D0%BA%D0%BB%D1%8E%D1%87%D0%B8%D1%82%D1%8C%D1%81%D1%8F_%D0%BA_%D0%95%D0%A1%D0%98%D0%90/).

## 2. Роли и ответственность

| Роль | Кто | Что делает |
|------|-----|------------|
| **Заявитель / оператор ИС** | АО «ЦРЗ РТ» | Регистрация организации и ИС, КЭП, заявки на тест/пром, правовые основания |
| **Руководитель организации** | Генеральный директор (или иное лицо с правом действовать без доверенности) | Подтверждённая УЗ в ЕСИА, КЭП руководителя, регистрация ЮЛ в ЕСИА |
| **Ответственный за Технологический портал** | Назначенный сотрудник Заказчика (ИТ / ИБ / администратор портала) | Регистрация ИС, сертификат ИС, переписка с СЦ |
| **Сопровождение (регион)** | Минцифры Республики Татарстан *(рекомендуется)* | Методическая поддержка, проверка комплектности, ускорение внутренней координации |
| **Исполнитель (разработчик)** | Подрядчик по разработке Assessment | Техпараметры redirect URI / scope, реализация OIDC после выдачи доступов, тест на стенде |
| **Оператор ЕСИА / СЦ** | Минцифры России / ситуационный центр ЭП | Приём заявок, тестовый и промышленный доступ |

### Письмо № 4 — заявка на **тестовую** среду ЕСИА (ключевое)

| Поле | Содержание |

| **Форма** | Заявка по форме из **Регламента информационного взаимодействия** (приложение — форма на подключение к тестовой среде) |

идентификация физического лица, ФИО, контакты (email/телефон — если доступны политикой согласия), при необходимости иные атрибуты **только после согласования** с оператором ЕСИА. Не запрашивать лишние scope «на будущее».

**Технические параметры, которые Исполнитель передаёт Заказчику для заявки:**

| Параметр | Значение |
|----------|----------|
| Redirect URI (callback) | `https://test.zakupki.tatar/api/esia.php?action=callback` |
| Стартовая страница входа | `https://test.zakupki.tatar/login.html` |
| Протокол | OpenID Connect / OAuth 2.0 (как в методических рекомендациях ЕСИА) |
| Цель | Идентификация и аутентификация участников тестирования |

## 4. Пошаговый календарный план (ориентир)

| Этап | Действие | Ответственный | Ориентир* |
|------|----------|---------------|-----------|
| A | КЭП руководителя + регистрация ЮЛ в ЕСИА | Руководитель АО | 3–10 р.д. |
| B | Приказ + доступ сотрудника к Технологическому порталу | АО | 1–3 р.д. |
| C | Регистрация ИС (и СМЭВ-мнемоника при необходимости) | АО (+ Минцифры РТ) | 5–15 р.д. |
| D | Выпуск КЭП / сертификата **на ИС** | АО (УЦ) | 3–10 р.д. |
| E | Письмо № 0 в Минцифры РТ (сопровождение) | АО | параллельно с C–D |
| F | Заявка тест → `sd@sc.digital.gov.ru` | АО | 1 р.д. на отправку |
| G | Ответ СЦ + настройка теста | СЦ + АО + Исполнитель | по регламенту СЦ |
| H | Отладка входа на `test.zakupki.tatar` | Исполнитель | 3–7 р.д. после доступов |
| I | Заявка на пром → `sd@sc.digital.gov.ru` | АО | после успешного теста |
| J | Пром + приёмка | АО + Исполнитель | 3–7 р.д. |

\*Сроки рассмотрения заявок СЦ зависят от федерального контура и комплектности документов; Исполнитель на них не влияет.

## 5. Что подготовить Заказчику заранее (чек-лист)

- [ ] Карточка ЮЛ АО «ЦРЗ РТ» (ОГРН, ИНН, полное наименование)  
- [ ] КЭП руководителя (действующий)  
- [ ] Приказ о назначении ответственного за Технологический портал ЕСИА  
- [ ] Краткое описание ИС Assessment (назначение, пользователи, ПДн, URL)  
- [ ] Перечень НПА-оснований (договор / положение / акты РТ о ЦРЗ / закупках — формулировки согласует юрист Заказчика)  
- [ ] Решение по СМЭВ: новая регистрация ИС или использование существующей мнемоники  
- [ ] Сертификат ключа ЭП **информационной системы** (требования — по Регламенту / методрекомендациям ЕСИА)  
- [ ] Согласованный список **scope**  
- [ ] Контакт для СЦ (ФИО, телефон, email)  

**Важно (требования 2025+):** для **новых** подключений действуют усиленные требования ИБ / OpenID Connect по актуальным Методическим рекомендациям Минцифры. Юристу и ИБ Заказчика нужно сверить комплект **до** подачи заявки на пром. Уже подключённые ранее чужие ИС не отменяют требований к **новой** ИС Assessment.

## 6. Что уже готово у Исполнителя (разработка)

На момент подготовки плана в модуле Assessment:

- кнопка «Войти через Госуслуги» на формах входа/регистрации (пока неактивна до доступов);  
- каркас API `https://test.zakupki.tatar/api/esia.php`;  
- конфигурация через `.env` (`ASMT_ESIA_ENABLED` и параметры);  
- сценарий после ключей: OIDC → создание/привязка пользователя → дозаполнение анкеты (ИНН и др.) → фиксация согласий 152-ФЗ.

До получения пакета из Письма № 6 полная интеграция **не может быть включена в пром**.

## 7. Рекомендуемые формулировки для юриста Заказчика (цель подключения)

*Пример (требует правовой вычитки Заказчиком):*

> Подключение информационной системы «Модуль Assessment» к ЕСИА осуществляется в целях идентификации и аутентификации физических лиц — участников процедур независимой оценки профессиональных знаний специалистов в сфере закупок, организуемых АО «Центр развития закупок Республики Татарстан», с использованием единой системы идентификации и аутентификации в соответствии с законодательством Российской Федерации.

В заявке лучше ссылаться на **конкретные пункты** правовых актов (указывает юрист АО / куратор от РТ).

## 8. Риски и как их снять

| Риск | Как снизить |
|------|-------------|
| Заявка отклонена из‑за неполного комплекта | Письмо № 0 в Минцифры РТ + сверка формы с актуальной версией Регламента |
| Нет мнемоники СМЭВ | Параллельно открыть трек регистрации ИС в СМЭВ |
| Долго ждут КЭП на ИС | Заказать сертификат ИС сразу после регистрации ЮЛ в ЕСИА |
| Scope «раздуты» | Согласовать минимум с Исполнителем до подачи |
| Путаница тест/пром | Сначала только тест; пром — отдельным письмом с номером тестовой заявки |

## 10. Итог для Заказчика (одно предложение)

**АО «ЦРЗ РТ» назначает ответственного, регистрирует организацию и ИС в ЕСИА (при необходимости — в СМЭВ), направляет заявки на тест и затем на пром на `sd@sc.digital.gov.ru` по формам Регламента; параллельно желательно запросить методическую поддержку Минцифры РТ; после ответа СЦ передаёт параметры Исполнителю для включения кнопки «Войти через Госуслуги» на `test.zakupki.tatar`.**
