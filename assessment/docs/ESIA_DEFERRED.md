# Оценка и ограничения ЕСИА (этап 4)

**Статус:** отложено до выдачи ключей / доступов Заказчиком.

## Что сделано сейчас

- Кнопка «Войти через Госуслуги» на `login.html` / `register.html` — **disabled** с пояснением.
- API-каркас: `public/api/esia.php` (`action=start|callback`) отвечает `503` при `ASMT_ESIA_ENABLED=0`.
- В `.env.example` подготовлены переменные `ASMT_ESIA_*`.

## Что нужно от Заказчика

1. Учётные данные ЕСИА (client_id, client_secret / сертификат — по регламенту).
2. Redirect URI: `https://test.zakupki.tatar/api/esia.php?action=callback`
3. Состав атрибутов профиля (ФИО, email, СНИЛС — что разрешено).

## После выдачи доступов

1. Выставить `ASMT_ESIA_ENABLED=1` и реквизиты в `.env`.
2. Реализовать OAuth code flow в `esia.php`.
3. Автосоздание / привязка `asmt_users`, дозаполнение анкеты (ИНН и т.д.).
4. Фиксация согласий 152-ФЗ при первом входе через ЕСИА.

Рекомендуется зафиксировать в Акте сдачи-приёмки:  
«Интеграция ЕСИА отложена до предоставления доступов Заказчиком; интерфейс-заглушка принята».

**План для Заказчика (письма, адресаты, шаги):** см. `Документы/План_подключения_ЕСИА.md`.
